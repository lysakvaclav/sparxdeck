# SparxDeck platform

The web app at `portal.sparxdeck.com`: Next.js 16 (App Router), Supabase (Postgres, Auth, Storage, EU region), next-intl (Czech and English), Tailwind 4.

## Setup

1. **Install dependencies** (inside this folder):

   ```bash
   npm install
   ```

2. **Create a Supabase project** at [supabase.com](https://supabase.com), region **Central EU (Frankfurt)**.

3. **Environment:** copy `.env.example` to `.env.local` and fill in the values from _Project Settings → API_. Never commit `.env.local`.

4. **Apply migrations** (no Docker or CLI login needed; `SUPABASE_DB_URL` is the "Session pooler" connection string from _Connect_ in the dashboard):

   ```bash
   npm run db:push        # applies supabase/migrations
   ```

   To regenerate `src/lib/supabase/database.types.ts` after a migration, link once with `npx supabase login` and `npx supabase link --project-ref <ref>`, then run `npm run db:types`.

5. **Auth settings** in the Supabase dashboard (_Authentication → URL Configuration_):
   - Site URL: `http://localhost:3001` (production: `https://portal.sparxdeck.com`)
   - Redirect URLs: `http://localhost:3001/**` (production: `https://portal.sparxdeck.com/**`)

   Alternatively push `supabase/config.toml` with `npx supabase config push`.

6. **Run:**

   ```bash
   npm run dev            # http://localhost:3001
   ```

## Scripts

| Script                               | What it does                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `npm run dev`                        | Development server on port 3001 (the landing page uses 3000)                                                |
| `npm run build`                      | Production build                                                                                            |
| `npm run lint` / `npm run typecheck` | ESLint / TypeScript                                                                                         |
| `npm test`                           | Unit tests, plus Row Level Security tests against the Supabase project in `.env.local` (skipped without it) |
| `npm run db:push`                    | Apply new migrations to the linked project                                                                  |
| `npm run db:types`                   | Regenerate database types after a migration                                                                 |

## Conventions

- **Multi-tenancy:** every tenant table has `organization_id` and Row Level Security. Each new table gets a policy and a test in `tests/rls.test.ts` proving another organization can't see it.
- **Cross-table writes** (creating an organization, accepting an invitation) go through `SECURITY DEFINER` functions in the migrations, not broad policies.
- **Texts** live in `messages/cs.json` (source) and `messages/en.json`; a test checks both have the same keys. The locale comes from a cookie, not the URL, so printed QR links (`/d/<token>`) never change.
- **Layout** uses logical CSS properties (`ps-`, `pe-`, `start-`, `end-`, `border-e`) so right-to-left languages mirror without changes.
- **E-mail** goes through Resend. Without `RESEND_API_KEY`, invitation links are shown in the UI to share by hand.
- **Design** follows the landing page: tokens in `src/app/globals.css`, Helvetica Now Display, monochrome with colour reserved for status.

## Auth e-mails

Supabase sends the sign-up confirmation, magic link, password reset and e-mail change messages. Our templates (Czech/English by the user's `locale` metadata, SparxDeck look) live in `supabase/templates/` and are generated by `node scripts/build-email-templates.mjs`. Their links go to `/auth/callback` with a `token_hash`, so they work in any browser.

To use them on the hosted project, either paste each file into _Authentication → Email Templates_ (subjects are in `supabase/templates/subjects.json`), or run `npx supabase config push` after linking the project.

For reliable delivery, set up Resend as custom SMTP in _Authentication → SMTP Settings_ (host `smtp.resend.com`, port `465`, user `resend`, password = Resend API key) with a verified sending domain. Supabase's built-in mailer allows only a few e-mails per hour.

## Rate limiting

Password sign-in runs in the browser (`src/app/(auth)/login/login-form.tsx`) so Supabase Auth applies its per-IP limit to each user rather than to our server. Keep it that way.
